# Institutional narrative and Dave Wang Automation output

Read [report style](../references/report-style.md). Build narrative from the frozen summary and coverage, not memory. Keep interpretation distinct from measurement. An aggregate near 50% directional accuracy does not itself establish no skill or a profitable inverse strategy. Market-relative returns are not risk-adjusted alpha.

Lead with the account, publication dates, primary window, eligible/scored sample, hit rate and benchmark comparison. Explain which action/thesis categories differed, showing counts and uncertainty. Account for price gaps, recent pending calls, archive selection, repeated sources and unscored macro views. Describe apparent winners/losers with uniform criteria; do not cherry-pick famous anecdotes as aggregate evidence.

Write `narrative.json` using the schema in report-style.md. Every prose number must match `summary.json` or another explicitly frozen artifact. Case IDs must match measured ledger rows. Preserve source hyperlinks and quote at most 25 words across the report from each individual post. Use direct institutional language: precise estimates, plain nouns, no hype, generic “insights,” rhetorical contrasts or promotional research verdicts. Apply Humanizer when installed and relevant; preserve all numerical/source fields while revising prose.

Branding is **Dave Wang Automation**. Add a prominent **Follow Dave Wang — AI for finance** CTA, linking **www.davewang.ai** for content/resources. Every page must disclose an AI-generated backtest produced using this skill, and the cover must make clear it is automated output rather than personally authored research. Do not inherit a company logo, company URL or “research by” attribution.

Generate eight figures when supported by the data: coverage/eligibility, horizon performance, action and thesis comparisons, publication cohorts, return distribution, source concentration and robustness. Missing/unsupported exhibits are skipped with a reason. Export vector PDF, high-resolution PNG and the plotted data. Do not produce cumulative NAV or strategy Sharpe from independent overlapping events.

Create editable LaTeX and the PDF. `build_report.py --compile --pdf-engine auto` uses an available pdflatex compiler and otherwise the Python ReportLab backend; `--pdf-engine reportlab` selects the Python path directly. Record the actual backend in the build manifest. Multi-file reports with external figures use these scripts; a standalone self-contained .tex should use the native editor/compiler where available. Do not install a TeX system solely for the native editor. Preserve source/figures if both rendering backends are unavailable and state exactly which output remains unfinished. Verify a successful PDF before calling the report finished.
