# Delivery checks

Complete these checks before delivering a study:

1. Source ID counts, author identity, publication bounds and per-post reviews reconcile. Coverage receipt names caps, unavailable material and partial intervals. No-call reviews are retained.
2. Dated security mappings, adjustments, calendar audits and required entry/exit bars are validated. No unsupported instrument receives a stock score. Pending and gap statuses remain separate.
3. `verification.json` passes. Call book and plan hashes match the frozen receipt. Primary counts and headline rates reconcile to ledger rows. Return and hit-rate denominators differ only for documented neutral treatment.
4. Narrative figures/case IDs match frozen data. Benchmark comparisons share the same source sample, direction and exact dates. Classification confidence is not presented as forecasting probability. Exploratory categories are not advertised as a proven strategy.
5. Chart manifests match outcomes and summaries. Read plotted-data CSVs and inspect all chart labels, units, intervals, counts and axes. Missing cells are not interpolated or styled as observations.
6. `validate_report.py` passes. Render and inspect **every PDF page**, including source/appendix/overflow pages. Check readable body text, intact hyperlinks, no clipped tables/labels, prominent CTA, correct brand and per-page AI/skill disclosure.

Deliver the PDF and `all-calls.csv`; offer the editable source/figures when useful. Mention the actual recovered universe and any material unfinished work in plain language. Do not link a raw user corpus or API response cache for public distribution. Keep current study data out of the installable skill/repository. Output hashes and manifests are local audit records, not user-facing microtext on every chart.

For skill changes, run the unit suite and synthetic offline evals. Test the complete workflow with a fresh temp directory and account/date settings different from the original study. Do not require a live paid API call for routine regression tests.
